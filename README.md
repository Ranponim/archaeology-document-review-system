# 고고학 보고서 교정·검수 시스템

PDF·HWP(X)·사진·도면을 공통 문서 모델로 연결하고, 규칙 검사와 LLM/VLM 분석이 만든 오류 후보를 고고학 전문가가 승인하는 시스템의 설계 문서다. 시스템은 원본을 자동 수정하거나 학술적 판단을 확정하지 않는다.

## 문서 상태

| 구분 | 상태 | 기준일 | 의미 |
| --- | --- | --- | --- |
| 시스템 설계 | 설계 검토 초안 | 2026-08-14 | 아래의 향후 구현 요구사항은 확정했지만 제품 구현은 시작 전이다. |
| 실제 자료 표본 | 샘플 검증 완료 | 2026-08-14 | 1차·2차·3차 교정 PDF의 동일 내용 10쪽씩, 총 30쪽과 연결 자산을 읽기 전용으로 검사했다. |

이 문서는 다음 세 종류의 문장을 구분한다.

- **관찰 사실**: 검증 스크립트와 사람이 확인한 표본 결과
- **분석·추론**: 관찰 사실에서 도출한 설계 판단이며 전체 자료에 대한 보장은 아님
- **향후 구현 요구사항**: 제품이 충족해야 하지만 현재 구현 완료를 뜻하지 않는 조건

## 1. 목표와 역할 분담 — 향후 구현 요구사항

검수 범위는 문서·사진·도면 사이의 명칭과 내용 통일, 오탈자와 표기 오류, 문맥 모순, 자산 대응과 누락, 본문 참조번호와 캡션 번호, 버전별 변경 이력이다.

> 프로그램이 문서를 구조화하고 명시적 비교를 수행하며, LLM/VLM은 의미 판단 후보를 만들고, 전문가는 최종 판단을 내린다.

| 역할 | 담당 |
| --- | --- |
| 파일 변환, 페이지 분리, 해시와 좌표 보존 | 코드 |
| 본문·표·사진·도면·캡션 추출 | 코드와 문서 파서 |
| 번호·식별자·수치·버전 비교 | 규칙 엔진 |
| 오탈자·문맥 오류 후보 | 텍스트 LLM |
| 사진·도면의 의미적 대응 후보 | VLM |
| 학술적 타당성, 후보 채택·기각, 최종 승인 | 고고학 전문가 |

## 2. 검증한 실제 자료 — 관찰 사실

### 2.1 입력 파일

검사일은 2026-08-14이며, 다음 세 PDF를 검사했다. 세 파일 모두 암호화되지 않았고 텍스트 추출이 가능했다.

| 버전 | 표본 파일 | 전체 쪽수 | 표본 물리 페이지 | 표본 인쇄 페이지 |
| --- | --- | ---: | --- | --- |
| 1차 | `11.8-115집 논산 산노리 산17-1번지 유적-본문-1차 교정.pdf` | 264 | 105–114 | 101–110 |
| 2차 | `11.19-115집 논산 산노리 산17-1번지 유적-본문-2차 교정.pdf` | 269 | 111–120 | 102–111 |
| 3차 | `11.21-115집 논산 산노리 산17-1번지 유적-본문-3차 교정.pdf` | 282 | 126–135 | 102–111 |

- 표본 규모: 버전별 연속 10쪽, 총 30쪽
- 파생 자료: 텍스트·좌표 JSON 30개와 1191×1684 RGB 페이지 렌더 30개
- 연결 자산 검색 범위: `도판(사진들)/Links`, `본문 도면`, `환경 도면`
- 원본 보존: 원본은 읽기 전용으로 사용했고 SHA-256 재검증에서 변경이 없었다.

### 2.2 페이지 대응

연속 구간 전체를 내용 기반으로 탐색한 결과, 10개 대응 행이 모두 세 버전에 연결되었다. 선택 점수는 `0.777581`, 추출 텍스트의 독립 평균 유사도는 `0.990107`, 최소 유사도는 `0.948217`이었다. 1차 인쇄 페이지가 2·3차보다 한 쪽 앞서므로 인쇄 페이지 번호만으로는 버전을 대응시킬 수 없다.

각 대응은 다음 네 값을 함께 보존한다.

```text
(문서 버전, 물리 페이지, 인쇄 페이지, 정규화 텍스트 지문)
```

### 2.3 버전 차이 후보

`1차→2차`, `2차→3차`, `1차→3차`를 각 10개 대응 행에서 비교해 후보 124건을 기록했다. 직접 비교 세 경로를 모두 세므로 앞 단계에서 생겨 유지된 수정은 `1차→3차`에도 다시 나타난다.

| 분류 축 | 값 | 건수 |
| --- | --- | ---: |
| 변경 유형 | 추가 | 71 |
|  | 삭제 | 2 |
|  | 수정 | 51 |
|  | 이동 | 0 |
| 검토 상태 | 확인됨 | 120 |
|  | 레이아웃 잡음 | 2 |
|  | 전문가 검토 필요 | 2 |
|  | 미해결 | 0 |
| 대표 규칙 | 도면·도판·표·사진 참조 | 66 |
|  | 교정 표기·띄어쓰기·괄호 반영 | 56 |
|  | 유구·유물 식별자 | 2 |

모든 후보에 버전, 물리·인쇄 페이지, 문단, 원문, 비교문, 규칙 결과, 신뢰도, 렌더 경로와 수동 검토 판단이 채워졌고 빈 근거 필드는 0건이었다. 대표 변화는 1차의 빈 도면·도판 번호가 2차에서 도면 57–60과 도판 85–90으로 채워진 사례, 띄어쓰기·문법 수정, 3차의 `(보강토)`·`장방형에`·`또한 주변으로` 추가다.

삭제 후보 2건은 같은 경계 사례가 두 비교 경로에 잡힌 것이다. 표본 마지막의 16호 토광묘 문장이 다음 쪽으로 이어지는지 표본 안에서 판별할 수 없어 전문가 검토 상태로 남겼다.

### 2.4 주석 추출 한계

세 PDF 전체와 선택한 30쪽에서 네이티브 PDF 주석 객체는 0건이었다. 따라서 이번 표본으로는 주석 작성자, 해결 상태, 댓글 스레드나 교정 지시 메타데이터를 추출할 수 있는지 검증하지 못했다. 관찰된 교정은 PDF 주석이 아니라 본문 문자열과 도면 레이블에 포함되어 있었다. 지층 순서를 나타내는 `→` 같은 본문 기호는 교정 주석으로 간주하지 않았다.

### 2.5 사진·도면 연결 상태

2·3차에서 도면 57–60과 도판 85–90, 총 10개의 고유 번호 참조를 추출했다. 1차의 빈 참조 칸 30회는 번호가 없는 발생으로 별도 보존했다.

| 상태 | 건수 | 참조 |
| --- | ---: | --- |
| 정확 연결 | 3 | 도면 58, 59, 60 |
| 복수 후보 | 4 | 도판 86, 88, 89, 90 |
| 원본 누락 | 1 | 도판 85 |
| 의미 검토 필요 | 2 | 도면 57, 도판 87 |

정확 연결된 세 도면은 `도면21. 2지점 유구+유물 편집.ai`의 서로 다른 영역이며, 각각 5–8호·9–12호·13–16호 토광묘 캡션에 대응한다. 도면 57은 선택 구간에 번호가 붙은 도면 캡션이 없어 의미 검토 상태다. 도판 JPEG 후보는 파일명과 보이는 표지만으로 선택한 2지점임을 확정할 수 없었고, 도판 85는 허용한 검색 범위에서 맞는 후보가 없었다.

## 3. 검증에서 도출한 판단 — 분석·추론

1. **페이지 번호는 단독 키가 아니다.** 판형과 앞부분 증감으로 물리·인쇄 페이지가 이동하므로 버전, 두 페이지 번호, 내용 지문을 결합해야 한다.
2. **버전 차이와 교정 의도는 다르다.** 문자열 차이는 재현할 수 있지만, 표본 경계의 삭제처럼 의도 판별에는 앞뒤 페이지와 전문가 판단이 필요하다.
3. **주석 없는 PDF가 정상 입력일 수 있다.** 교정 이력을 PDF 주석 객체에만 의존하면 이번 자료의 변경 대부분을 놓친다.
4. **자산 번호 일치만으로 정확 연결할 수 없다.** 다른 지점의 같은 번호, 여러 조사 단계 사진, 하나의 AI 파일 안 여러 도면 영역을 구분해야 한다.
5. **확정 자산도 영역 단위 식별이 필요하다.** 도면 58–60은 같은 AI 원본을 공유하므로 파일 경로만 저장하면 서로 구별되지 않는다.
6. **현재 수치는 표본 기준선이다.** 30쪽 결과를 전체 보고서, HWP(X), 스캔 PDF 또는 다른 유적의 성능으로 일반화하지 않는다.

## 4. 공통 문서 모델 — 향후 구현 요구사항

모든 입력 형식은 다음 필드를 가진 공통 모델로 변환한다. 필수값을 얻지 못하면 빈 문자열로 대체하지 않고 오류 상태와 원인을 기록한다.

| 영역 | 필수 필드 |
| --- | --- |
| 문서 식별 | `document_id`, `source_file_id`, 원본 경로, SHA-256, 형식, 바이트 크기 |
| 버전 계보 | `lineage_id`, `version_id`, `revision_stage`, 작성일, `parent_version_id` |
| 페이지 대응 | `page_id`, 물리 페이지, 인쇄 페이지, 정규화 지문, 대응 행 ID, 앞뒤 페이지 ID |
| 내용 블록 | `block_id`, 유형(문단·표·캡션·사진·도면·각주), 원문, 페이지 좌표, 읽기 순서 |
| 고고학 개체 | 유적·지점·구역·유구·유물 식별자와 연결된 블록·자산 ID |
| 자산 식별 | `asset_id`, 원본 해시, 매체 형식, 캡션, 파일 내부 영역, 축척·방위·조사 단계 |
| 후보 근거 | `candidate_id`, 비교 버전, 원문·비교문, 규칙/모델 버전, 신뢰도, 근거 페이지·블록·자산·렌더 |
| 오류와 변환 | `processing_status`, `error_code`, 단계, 도구·버전, 원본 보존 여부, 재시도 가능 여부 |
| 전문가 승인 | 검토 상태, 익명 검토자 ID, 채택·기각·수정 후 채택·보류, 사유, 시각, 이전 결정 |

권장 계층은 다음과 같다.

```text
원본 자료 → 읽기 전용 입력 표준화 → 공통 문서 모델
         → 고고학 개체 묶음 → 규칙/LLM/VLM 후보
         → 전문가 승인 → 감사 가능한 검수 보고서
```

페이지는 처리 단위이고, 검수 단위는 동일 유구·유물에 연결된 본문·도면·사진·표·캡션 묶음이다.

## 5. 입력과 실패 상태 — 향후 구현 요구사항

### 입력 처리

- PDF는 최종 지면, 물리·인쇄 페이지, 배치와 캡션 위치의 기준으로 사용한다. 텍스트 PDF와 스캔 PDF를 구분하고 후자는 OCR 결과와 원본 이미지를 함께 보존한다.
- HWPX는 XML 논리 구조를 추출하되 PDF 지면과 교차 검증한다.
- HWP는 원본을 변경하지 않는 별도 변환 과정을 사용하고 변환 도구와 버전을 남긴다.
- AI는 PDF 호환 미리보기 존재 여부를 먼저 검사한다. 렌더 이미지와 파일 내부 영역·레이어·텍스트 정보를 함께 연결한다.
- 사진은 원본 해상도와 메타데이터를 보존하고 촬영 방향, 시점, 조사 단계, 유구·유물 식별정보를 관리한다.

### 실패와 제약

다음 조건을 성공 결과와 분리된 구조화 오류로 기록하고 원본을 자동 수정하지 않는다.

- 암호화·손상·미지원 형식, HWP/HWPX/AI 변환 실패
- 텍스트 계층 부재, OCR 저신뢰, 문자 인코딩·폰트·글상자·표·각주 누락
- 물리·인쇄 페이지 불일치, 페이지 재배치, 한 비교가 여러 페이지 경계를 넘는 경우
- 표본 시작·끝 경계 때문에 앞뒤 문맥이 없는 경우
- PDF 주석 객체 부재 또는 주석 작성자·상태 추출 실패
- 캡션 번호 공란, 중복 번호, 자산 없음, 복수 후보, 의미 판단 필요
- AI 호환 미리보기 부재, 렌더 실패, 하나의 파일에 여러 의미 영역 존재
- 원본·파생물 해시 불일치, 근거 경로 이탈, 필수 근거 필드 누락

오류 상태의 최소 집합은 `input_error`, `conversion_error`, `extraction_error`, `alignment_error`, `evidence_incomplete`, `asset_missing`, `asset_multiple`, `semantic_review`, `manual_review`, `unresolved`로 한다.

## 6. 전문가 승인 흐름 — 향후 구현 요구사항

```text
후보 생성
  → 근거 완전성 검사
  → 기계 규칙 또는 모델별 분류
  → 전문가 검토: 채택 / 기각 / 수정 후 채택 / 보류
  → 결정 사유와 변경 이력 고정
  → 승인된 결과만 검수 보고서에 반영
```

- 확정적 기계 오류도 원본에 자동 반영하지 않는다.
- `manual_review`, `semantic_review`, `multiple`, `missing`, `unresolved`는 전문가 승인 없이는 확정 상태로 전환하지 않는다.
- 모든 결정은 후보의 원문·비교문, 페이지·좌표, 자산 영역, 규칙/모델 버전과 연결한다.
- 결정이 바뀌면 이전 값을 덮어쓰지 않고 새 이력 항목을 추가한다.

## 7. 구현 우선순위와 합격 기준 — 향후 구현 요구사항

각 단계는 앞 단계의 산출물을 입력으로 사용한다. 아래 기준은 현재 표본에서 재현할 최소 게이트이며, 다른 문서에 대한 일반 성능 평가는 별도 보류 집합으로 수행한다.

### 1단계: PDF 입력·페이지 대응·규칙 검사

구현 범위는 입력 무결성 검사, 텍스트·좌표·렌더 추출, 버전 계보, 연속 페이지 대응, 명시적 번호·식별자·표기 규칙, 근거 패키지다.

합격 기준:

1. 고정한 세 SHA-256 입력에서 3개 PDF 읽기, 10개 대응 행, JSON 30개, 렌더 30개를 매 실행 동일하게 생성한다.
2. 모든 대응 행에 버전·물리 페이지·인쇄 페이지·정규화 지문이 있고, 표본 기준 평균 유사도 `0.990107`, 최소 `0.948217`을 재현한다.
3. 세 비교 경로에서 후보 124건과 변경 유형 `71/2/51/0`을 재현하며 필수 근거 누락은 0건이다.
4. 30쪽 전부의 읽기 순서·캡션 위치·표기·도면 배치를 전문가가 확인하고, 모든 후보에 채택 가능한 상태와 사유를 기록한다.
5. 재실행 전후 원본 SHA-256이 동일하고, 오류 입력은 구조화 오류로 종료된다.

### 2단계: 사진·도면 후보 연결

구현 범위는 캡션·본문 참조 추출, 번호·유적·시대·유구 의미 검색, 이미지 미리보기, AI 파일 내부 영역 연결이다.

합격 기준:

1. 표본의 고유 참조 10개와 번호 없는 1차 발생 30회를 빠짐없이 재현한다.
2. 상태 분포 `exact=3`, `multiple=4`, `missing=1`, `semantic_review=2`를 재현하고 모든 후보·기각에 검색 근거를 남긴다.
3. `exact` 세 건은 원본/미리보기 해시와 파일 내부 영역 캡션이 모두 일치해야 하며 전문가가 렌더를 확인한다.
4. 복수·누락·의미 검토 상태는 자동 확정하지 않고 전문가의 선택 또는 보류 사유를 기록한다.
5. 허용한 자산 루트 밖 경로, 확장자와 실제 매체가 다른 파일, 해시가 달라진 미리보기는 전부 거부한다.

### 3단계: LLM/VLM 의미 판단

구현 범위는 문맥 모순, 설명·캡션 불일치, 사진·도면 구조 대응을 판정하는 후보 생성이다. 모델은 1·2단계의 구조화 근거만 입력으로 사용한다.

합격 기준:

1. 독립된 전문가 2인이 합의한 텍스트 후보 100건 이상과 사진·도면 쌍 30건 이상을 보류 평가 세트로 고정한다.
2. 보류 세트에서 후보 정밀도 `0.85` 이상, 재현율 `0.80` 이상을 충족하고 오류 유형별 수치를 함께 공개한다.
3. 고정한 모델·프롬프트·입력에서 두 번 실행한 후보 ID 집합의 일치율이 `0.95` 이상이어야 한다.
4. 모델 출력 100%에 원문 또는 이미지 영역, 비교 대상, 모델·프롬프트 버전, 신뢰도와 판단 근거가 있어야 한다.
5. 전문가가 승인하지 않은 후보의 자동 수정률은 `0%`여야 하며, 채택·기각·보류 결정과 사유를 감사 로그에 남긴다.

## 8. 평가 지표 — 향후 구현 요구사항

- 전문가가 실제 수정한 오류 중 시스템이 찾은 비율(재현율)
- 시스템 후보 중 전문가가 채택한 비율(정밀도)
- 오류 유형·입력 형식·버전 단계별 정밀도와 재현율
- 사진·도면 연결 상태별 정확도와 보류율
- 전문가 검토 시간과 후보당 처리 시간
- 동일 입력 재실행 시 페이지 대응·후보·근거의 안정성
- 원본 해시 불변, 필수 근거 완전성, 승인 없는 자동 수정 0건

현재 표본의 수치와 수동 판단 근거는 `tmp/sample-validation/` 아래 검증 산출물에 보존되어 있다. 이 디렉터리는 개발 검증 자료이며 제품 구현 자체가 아니다.
