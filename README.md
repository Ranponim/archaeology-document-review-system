# 고고학 보고서 LLM 기반 교정·검수 시스템

## 문서 상태

- 상태: 설계 검토 초안
- 작성일: 2026-08-14
- 목적: 대용량 고고학 보고서의 본문·사진·도면·캡션을 구조화하고, 코드와 LLM/VLM을 결합해 전문가 검수 후보를 생성하는 시스템의 기본 방향을 정리한다.
- 주의: 이 문서는 아직 확정된 구현 명세가 아니다. 실제 자료의 구성과 검수 단계의 관계를 확인한 뒤 보완한다.

## 1. 목표

100MB 이상의 대형 고고학 보고서를 대상으로 다음 항목을 검수한다.

1. 문서·사진·도면 사이의 명칭과 내용 통일
2. 오탈자, 띄어쓰기, 표기 오류 교정
3. 문단 및 페이지 사이의 문맥 오류와 모순 탐지
4. 도면과 사진의 대응 관계 및 누락 가능성 확인
5. 그림·표·캡션·본문 참조번호의 일관성 확인
6. 1차·2차·3차 검수 및 최종 승인 과정의 변경 이력 관리

시스템의 역할은 보고서를 자동으로 확정 교정하는 것이 아니라, 근거가 있는 오류 후보를 전문가에게 제시하고 전문가의 판단을 축적하는 것이다.

## 2. 핵심 원칙

> LLM에게 전체 문서를 한 번에 읽게 하는 것이 아니라, 프로그램이 문서를 구조화하고 LLM에게 의미 판단만 맡긴다.

역할은 다음과 같이 나눈다.

| 역할 | 담당 |
|---|---|
| 파일 변환과 페이지 분리 | 코드 |
| 본문·표·사진·도면·캡션 추출 | 코드 및 문서 파서 |
| 개체 식별과 명시적 번호 비교 | 코드 |
| 오탈자와 문맥 오류 후보 탐지 | LLM |
| 사진·도면의 의미적 대응 판단 | VLM |
| 학술적 타당성 및 최종 승인 | 고고학 전문가 |

## 3. 현재 제안 구조

```text
원본 자료
├─ PDF
├─ HWP
├─ HWPX
├─ Illustrator 원도면(.ai)
└─ 현장 사진
        ↓
입력 표준화
        ↓
공통 문서 모델
├─ 페이지
├─ 문단/텍스트 블록
├─ 표
├─ 사진
├─ 도면
├─ 캡션
├─ 각주
└─ 좌표·스타일·원본 위치
        ↓
고고학 개체 묶음
유적 → 지점/구역 → 유구 → 유물 → 본문/도면/사진/표
        ↓
검수 엔진
├─ 규칙 기반 검사
├─ 텍스트 LLM 검사
├─ 멀티모달 VLM 검사
└─ 문서 전체 교차 검사
        ↓
전문가 검토
├─ 채택
├─ 기각
├─ 수정 후 채택
└─ 판단 보류
        ↓
검수 보고서 및 학습·평가 데이터
```

## 4. 입력 형식별 처리 원칙

### PDF

- 최종 지면, 페이지 번호, 배치, 캡션 위치를 확인하는 기준으로 사용한다.
- 텍스트가 좌표 단위로 저장되거나 스캔 이미지일 수 있으므로 레이아웃 분석과 OCR이 필요하다.
- 페이지를 분리하되, 앞뒤 문맥과 본문·그림·캡션 관계는 보존한다.

### HWPX

- XML 기반 구조에서 본문, 표, 스타일, 개체, 구역 정보를 추출한다.
- PDF보다 내용 구조를 복원하기 유리하므로 가능하면 논리 구조의 기준 자료로 사용한다.
- 최종 PDF와 비교해 페이지 이동, 배치 변화, 누락 여부를 검사한다.

### HWP

- 바이너리 형식과 버전 차이를 고려한 전용 파서 또는 안전한 중간 형식 변환이 필요하다.
- 원본 파일을 변경하지 않고 변환본과 변환 기록을 별도로 보관한다.
- 변환 과정에서 수식, 표, 글상자, 이미지, 각주가 누락되지 않았는지 확인한다.

### Illustrator(.ai)

- 가능하면 PDF 호환 저장 여부를 확인한다.
- AI를 SVG 또는 PDF로 변환해 텍스트, 좌표, 경로, 레이어 정보를 추출한다.
- LLM에는 AI 파일 자체만 전달하지 않고 다음 두 자료를 함께 제공한다.
  - 사람이 보는 렌더링 이미지
  - 코드가 추출한 텍스트·경로·레이어의 구조화 정보

### 현장 사진

- 원본 해상도와 메타데이터를 보존한다.
- 촬영 시점, 방향, 조사 단계, 축척, 유구·유물 식별정보를 가능하면 함께 관리한다.
- 사진과 도면은 픽셀 일치가 아니라 시점과 조사 단계를 고려한 구조적 대응으로 판단한다.

## 5. 페이지보다 중요한 검수 단위

페이지는 처리 단위로 사용하되, 실제 검수의 기준은 고고학 개체 묶음으로 둔다.

```text
Archaeology Object: SITE_A_FEATURE_017
├─ 본문: p.124 문단 3~5
├─ 도면: p.125 그림 7 / 원도면 A_SECTION_003.ai
├─ 사진: PHOTO_125_03, PHOTO_125_04
├─ 캡션: 유구 전경, 토층 단면
├─ 표: 유구 속성표 17번 행
└─ 검수 이력: 원고 → 1차 → 2차 → 3차 → 최종본
```

이 구조를 사용하면 페이지가 달라도 동일 유구 또는 유물과 관련된 자료를 함께 검수할 수 있다.

## 6. 필요한 검수 유형

### 규칙 기반으로 우선 처리할 항목

- 그림·도판·표 번호의 존재 여부와 연속성
- 본문 참조번호와 실제 캡션 번호 비교
- 유구·유물 번호와 명칭의 정확한 문자열 비교
- 고도, 길이, 수량, 연대 등 숫자 비교
- 누락 페이지와 중복 페이지
- 동일 캡션의 중복 또는 연결되지 않은 이미지
- 파일 버전과 검수 단계의 순서 확인

### LLM이 보조할 항목

- 오탈자와 문장 오류
- 전문용어와 띄어쓰기 통일
- 앞뒤 문단의 위치·방향·시대·수량 모순
- 설명과 캡션 사이의 의미적 불일치
- 다른 페이지에 흩어진 동일 개체 설명의 모순

### VLM과 전문가가 함께 볼 항목

- 사진에 보이는 구조가 도면에 표현되어 있는지
- 도면의 윤곽, 층위, 방향과 사진의 관찰 내용이 대응하는지
- 사진과 도면이 서로 다른 조사 단계 또는 시점을 나타내는지
- 도면 누락 또는 과도한 단순화 가능성
- 학술적 해석이 필요한 불일치

## 7. 기존 설계에서 추가해야 할 부분

### 7.1 입력 표준화 계층

PDF, HWP, HWPX, AI, 이미지가 혼재하므로 모든 자료를 공통 내부 형식으로 변환해야 한다. 변환 결과에는 원본 파일, 원본 위치, 페이지 또는 개체 좌표, 변환 도구와 버전, 변환 오류를 기록한다.

### 7.2 버전과 검수 이력 모델

원고·1차·2차·3차·최종본을 독립 문서로만 취급하지 않고 동일 문서 계보의 버전으로 연결한다. 문장, 표, 사진, 캡션, 도면 단위의 추가·삭제·수정·이동을 추적해야 한다.

### 7.3 오류 분류표와 심각도

최소한 다음 상태가 필요하다.

- 확정적 기계 오류
- 높은 가능성의 내용 불일치
- 학술적 판단 필요
- 입력 또는 변환 품질 문제
- 판단 불가

오류 유형별로 자동 수정 가능 여부와 전문가 승인 필요 여부를 정한다.

### 7.4 근거와 출처 추적

모든 지적에는 다음 정보가 있어야 한다.

- 원본 파일과 버전
- 페이지, 문단, 표 셀 또는 이미지 영역
- 원문과 제안문
- 비교 대상 자료
- 판단 근거
- 신뢰도
- 사용한 규칙 또는 모델 버전
- 전문가의 최종 판단

### 7.5 예외 처리

- 암호화되거나 손상된 파일
- HWP 변환 실패
- 문자 인코딩과 폰트 문제
- 스캔 품질 저하와 OCR 오류
- 한 페이지에 여러 캡션이 있는 경우
- 사진과 도면의 대응 개체를 찾지 못한 경우
- 개정본에서 페이지 번호가 크게 이동한 경우

### 7.6 평가 체계

단순히 AI가 많은 오류를 찾았는지가 아니라 다음을 측정한다.

- 전문가가 실제 수정한 오류 중 AI가 찾은 비율
- AI가 제시한 오류 중 전문가가 채택한 비율
- 오류 유형별 성능
- 문서 형식별 성능
- 전문가 검토 시간 절감
- 동일 입력 재실행 시 결과 안정성

## 8. 실제 데이터 준비 요청

### 가장 먼저 필요한 최소 샘플 묶음

전체 보고서보다 먼저 동일한 범위를 나타내는 10~30페이지 정도의 소규모 묶음을 준비하는 것이 좋다.

1. 원고 또는 검수 전 문서
2. 1차 검수본
3. 2차 검수본
4. 3차 검수본
5. 최종 승인본
6. 해당 범위의 원본 사진
7. 해당 범위의 Illustrator 원도면
8. 최종 PDF
9. 가능하면 HWP 또는 HWPX 원본
10. 검수자가 남긴 주석, 교정표, 메모 또는 변경 지시서

### 자료마다 있으면 좋은 메타데이터

- 보고서명과 내부 관리번호
- 파일의 검수 단계와 작성일
- 검수자 역할 또는 전문 분야(개인정보 대신 익명 코드 가능)
- 페이지 번호 체계: 파일 페이지와 인쇄 페이지
- 유적·지점·구역·유구·유물 식별번호
- 사진번호, 촬영 방향, 촬영 시점, 조사 단계
- 도면번호, 도면 종류, 축척, 방위, 레이어 명명 규칙
- 오류 또는 수정 사유
- 최종 채택·기각 여부

### 보안과 개인정보

- 실명, 연락처, 위치정보 등 불필요한 개인정보는 제거하거나 익명화한다.
- 외부 전송이 금지된 문서인지 확인한다.
- 원본은 읽기 전용으로 보존하고 모든 파생 파일은 별도 저장한다.
- 파일 해시와 처리 기록을 남겨 원본과 결과의 대응을 보장한다.

## 9. 현재 가장 중요한 확인 사항

다음 관계가 실제 자료에서 추적 가능한지 확인해야 한다.

```text
동일 보고서 원고
→ 1차 검수본
→ 2차 검수본
→ 3차 검수본
→ 최종 승인본
```

각 단계의 수정 흔적과 최종 승인 여부를 대응시킬 수 있다면, 이 자료를 시스템의 평가용 정답 데이터로 구성할 수 있다. 수정 흔적이 남아 있지 않고 완성본만 존재한다면 버전 간 자동 비교와 전문가 확인을 결합해 정답 데이터를 별도로 구축해야 한다.

## 10. 다음 설계 단계

1. 검수본들의 버전 관계와 수정 흔적 보존 여부 확인
2. 최소 샘플 묶음 선정
3. 실제 파일별 구조와 변환 가능성 점검
4. 오류 분류표 초안 작성
5. 공통 내부 데이터 모델 확정
6. 데이터 준비 방식 2~3개 비교 후 권장안 승인
7. 확정 설계 문서 및 구현 계획 작성
