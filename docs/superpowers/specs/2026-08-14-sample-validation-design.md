# 실제 교정본 샘플 검증 설계

## 목적

`src`에 보관된 논산 산노리 보고서 자료를 이용해 README의 제안 구조가 실제 자료에 적용 가능한지 검증한다. 동일한 본문 구간 10페이지를 1차·2차·3차 교정본에서 각각 비교해 총 30페이지를 검사하고, 그 구간과 관련된 사진·도면의 연결 가능성도 확인한다.

## 범위

- 입력 PDF: 본문 1차·2차·3차 교정본
- 표본: 세 버전에서 대응되는 동일한 연속 본문 10페이지
- 연결 자료: 선택 구간에 등장하는 캡션, 사진 파일, 본문 도면 및 환경 도면
- 최종 변경: 검증 결과와 구체화된 요구사항을 반영한 `README.md`
- 원본 정책: `src`의 파일은 읽기 전용으로 다루며 수정·이동·이름 변경을 하지 않는다.

표지·목차만 있는 PDF, 도판 전체, 부록 전체, 모든 사진과 모든 AI 파일의 전수 검사는 이번 범위에서 제외한다.

## 표본 선정

세 본문 PDF의 페이지 수, 페이지 라벨, 추출 가능 텍스트 및 교정 주석을 조사한다. 다음 조건을 가장 많이 만족하는 동일 구간을 선택한다.

1. 세 버전 모두에 대응 페이지가 존재한다.
2. 본문뿐 아니라 그림·표·사진 또는 도면 참조와 캡션이 포함된다.
3. 유적·지점·유구·유물 식별정보 중 하나 이상을 포함한다.
4. 문단과 페이지를 넘는 문맥을 확인할 수 있다.
5. 실제 교정 또는 주석의 흔적이 존재한다.

PDF 물리 페이지와 인쇄 페이지가 다르면 둘을 별도로 기록한다. 페이지 삽입·삭제로 물리 페이지가 어긋난 경우 제목, 첫 문장, 개체명과 캡션을 조합해 대응시킨다.

## 검증 절차

### 1. 입력 조사

각 PDF의 파일 크기, 페이지 수, 암호화 여부, 텍스트 추출 가능 여부, 페이지 라벨, 주석 수를 기록한다. 사용할 수 없는 기능이나 손상된 파일은 실패로 숨기지 않고 입력·변환 품질 문제로 분류한다.

### 2. 페이지 대응

페이지별 정규화 텍스트 지문과 제목·개체 식별자를 이용해 세 버전의 대응 관계를 찾는다. 연속성이 유지되는 10페이지를 표본으로 확정하고 선정 근거를 남긴다.

### 3. 버전 비교

페이지와 문단 단위로 추가·삭제·수정·이동 후보를 구분한다. 다음 항목을 우선 검사한다.

- 유구·유물·지점 명칭의 변화
- 그림·도판·표·사진 참조번호와 캡션 번호
- 수량, 치수, 고도, 방향, 시대 등의 값
- 맞춤법·띄어쓰기·전문용어 변화
- 교정 주석의 내용과 다음 버전 반영 여부

텍스트 추출 순서가 레이아웃과 달라 발생한 차이는 내용 수정과 분리한다.

### 4. 사진·도면 연결

표본의 캡션과 본문 참조에서 파일명 후보를 만들고 `src/도판(사진들)/Links`, `src/본문 도면`, `src/환경 도면`에서 대응 자료를 찾는다. 정확 일치, 복수 후보, 미발견을 구분한다. 파일명만으로 의미적 동일성을 확정하지 않으며, 렌더링 가능한 자료는 시각 확인을 보조 근거로 사용한다.

### 5. README 반영

검증 결과로 다음을 구체화한다.

- 실제 입력 자료와 버전 계보
- 페이지 대응 키와 공통 문서 모델의 필수 필드
- 검출 가능한 오류와 사람 판단이 필요한 오류의 경계
- 근거·출처 및 변환 품질 기록
- 예외 처리와 최소 샘플 준비 방식
- 구현 우선순위와 합격 기준

관찰되지 않은 기능은 구현 완료로 표현하지 않고, 확인된 사실·추론·향후 요구사항을 명확히 구분한다.

## 산출물

- 표본으로 사용한 파일과 페이지 범위
- 페이지 대응 및 버전 차이 요약
- 캡션·사진·도면 연결 결과
- 도구와 입력 형식의 제약 사항
- 실제 검증 결과가 반영된 완성형 `README.md`

중간 추출물과 렌더링 이미지는 `tmp/` 아래에만 두며 최종 산출물로 취급하지 않는다.

## 완료 조건

1. 동일한 연속 10페이지가 세 교정 단계에서 대응되어 총 30페이지가 검사된다.
2. 텍스트·번호·명칭·수치·주석 중 실제로 검사 가능한 항목과 결과가 기록된다.
3. 표본 구간의 사진·도면 연결이 정확 일치, 복수 후보, 미발견으로 분류된다.
4. 한계와 실패 사례가 README의 예외 처리 및 구현 요구사항에 반영된다.
5. README가 실제로 확인된 자료와 아직 구현해야 할 기능을 혼동하지 않는다.
